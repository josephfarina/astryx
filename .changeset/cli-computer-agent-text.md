[feat] The CLI installed for the computer keeps agent text for the whole computer: one skill file at `~/.agents/skills/astryx/SKILL.md` and `~/.claude/skills/astryx/SKILL.md` (plus the skill folder of Continue, Kiro, or Windsurf when that tool is installed), from the same source as a project's agent-docs block but with no version, telling agents to follow a project's own agent docs inside that project. It writes the text on its first run and after each switch to a newer release, in the background, so no command waits; package install scripts never write it. `astryx init --user` writes it now, in any folder, and `--agent claude,codex` limits it to the files those agents read (every agent tool the docs list is accepted). `astryx init --user --remove-agents` removes it and turns it off. The choice is kept in `astryx/settings.json` in the per-user configuration folder. Each file records a hash of its text, so a file a person edited is never overwritten or removed, and any file there that Astryx did not write, or a symlink, is kept. `init --user` warns, while still writing, when no `astryx` command on the computer runs the Astryx CLI, and its `init.user` receipt lists each file, what happened to it, and why a file was kept. Outside a project, `astryx doctor` adds a `computer-agent-text` check (info only) that says whether the text is present, matches the release that answered, was edited, or is turned off. A cache or configuration folder set through `XDG_CACHE_HOME`, `XDG_CONFIG_HOME`, `LOCALAPPDATA`, or `APPDATA` is used only when it is an absolute path.
