[feat] Install the CLI once for your computer (`npm i -g @astryxdesign/cli`) and run `astryx` in any folder. In a project, the CLI release equal to the project's `@astryxdesign/core` answers, whichever copy of the CLI you start: a copy hands the run to the project's own CLI when that CLI matches its Core, and otherwise to the matching release, which it installs once into your per-user cache (from the installed Core, else the lockfile, else the declared range). The hand-off keeps the arguments, folder, standard streams, and exit status. Outside a project, the copy installed for your computer answers with its own release; commands that read Core use the Core of that release there, installed into the cache when first needed. Nothing that worked before breaks: when the matching release cannot be obtained (offline, a registry without it, an unwritable cache), the run is answered as it was before global mode, by the project's own CLI if it installs one, else by the copy you started, with one warning line on standard error (`astryx: could not get Astryx <version> to match this project's Core (<reason>); answering with CLI <version> instead`) and `meta.answeredBy.copy: "fallback"` in JSON. The new `ERR_VERSIONS_UNAVAILABLE` is kept for runs nothing can answer: the project's own CLI is installed but cannot start, or a command that needs Core outside a project cannot install it. The CLI starts npm from npm's own entry file with the running Node, never through a shell, and reads a project's declared Core range only when it is a plain version range.

Every successful `--json` result now carries `meta.answeredBy` (`cli`, `core`, `copy`: `project`, `matched`, `carried`, or `fallback`), typed in `CLIResponse` and described in the output envelope docs. In text mode, a run answered by anything other than the project's own CLI prints one `astryx: answered by …` line on standard error. Printed commands start with a name that reaches the same release: the project's runner when its own CLI answers, `astryx` outside a project for the copy installed for the computer, and otherwise the CLI package pinned to the answering version (`npx @astryxdesign/cli@0.7.2`). The new `ERR_PROJECT_REQUIRED` code names a command that needs a project. See `astryx docs cli/install-once`.
